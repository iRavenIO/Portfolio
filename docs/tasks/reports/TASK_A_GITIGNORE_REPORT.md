## Problem Statement

### Root Cause

**Inconsistent Canonical Form**

The `cfactory` helper script (used during factory bootstrap) generates `.gitignore` entries in this format:

```
.claude/cache/         # Generated by cfactory
docs/tasks/reports/    # Generated by cfactory
```

However, `validate-policies.sh` check #57 expected exact matches without trailing comments:

```bash
grep -qxF ".claude/cache/" .gitignore
grep -qxF "docs/tasks/reports/" .gitignore
```

This caused validation failures even when `.gitignore` was correctly configured.

### Affected Components

1. `.claude/scripts/validate-policies.sh` — Check #57 (gitignore entries)
2. `.claude/runbooks/bootstrap-new-repo.md` — Step 2 (gitignore setup documentation)

### Discovery Context

Issue was identified during validation of the factory bootstrap process. The cfactory helper script correctly generated `.gitignore` entries, but the validation script rejected them due to format mismatch.

## Solution Overview

### Design Principles

1. **Backward Compatibility:** Support both legacy (no comments) and canonical (with comments) formats
2. **Flexible Validation:** Use regex patterns instead of exact string matching
3. **Documentation Alignment:** Update runbook to reflect actual generated output
4. **Negative Validation:** Add checks to prevent accidental exclusion of required directories

### Implementation Strategy

**Phase 1: Validation Script Enhancement**

- Replaced exact match (`grep -qxF`) with regex match (`grep -qE`)
- Pattern: `^\.claude/cache/(\s+#.*)?$` matches both:
  - `.claude/cache/` (legacy)
  - `.claude/cache/         # Generated by cfactory` (canonical)

**Phase 2: Negative Checks**

- Added checks #59 and #60 to prevent accidental exclusion:
  - Ensure `docs/` is not excluded
  - Ensure `.claude/` is not excluded
- Prevents common misconfigurations that would break the factory

**Phase 3: Documentation Sync**

- Updated `bootstrap-new-repo.md` Step 2 to show canonical .gitignore entries
- Removed outdated note about helper script using different format
- Added clarification that both formats are valid

```diff
+   echo "❌ Check #60 FAILED: .gitignore must NOT exclude .claude/"
+   FAIL_COUNT=$((FAIL_COUNT + 1))
+ fi
```

### What Went Well

3. **Backward Compatibility:** Regex solution elegantly supports both old and new formats without breaking existing repos

### Technical Insights

1. **Regex Pattern Design:**
   - Pattern `^\\.claude/cache/(\s+#.*)?$` is robust:
     - `^` and `$` enforce full-line match
     - `(\s+#.*)?` makes trailing comments optional
     - Escaping `.` prevents wildcard matching

2. **Negative Validation Value:**
   - Checks #59 and #60 prevent silent failures from overly broad exclusions
   - Example: `.gitignore` containing `docs/` would break factory documentation system

3. **Test Coverage Strategy:**
   - 33 tests provided comprehensive coverage:
     - 6 tests for check #57 (both formats, missing entries, partial matches)
     - 4 tests each for checks #59 and #60 (presence, absence, false positives)
     - 5 backward compatibility tests
     - 3 negative tests (intentional failures)

### Process Improvements

1. **Validation-First Development:**
   - Starting with validation script changes ensured tight alignment with requirements
   - Test suite was written in parallel with implementation, catching issues early

2. **Runbook Accuracy:**
   - Bootstrap runbooks should always reflect actual tool output, not idealized versions
   - This reduces friction during factory adoption in new repos

3. **Regex Over Exact Match:**
   - For validation checks that may have formatting variations, regex is more maintainable than exact string matching
   - Trade-off: slightly more complex patterns, but greater flexibility
