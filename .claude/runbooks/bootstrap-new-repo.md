# Runbook: Bootstrap the Factory in a New Repository

## When to Use

Use this runbook when setting up the autonomous multi-agent software factory in a new repository. This includes copying the factory infrastructure, adapting it to the new project, and verifying that all components work.

## Prerequisites

- You have a target repository (new or existing) where you want to deploy the factory
- The target repo has a `.git` directory (is a git repository)
- You have Node.js, npm, and git installed on your system
- You have the source factory repository available (to copy from)

## Steps

### 1. Copy Factory Infrastructure

**From source repo, copy these directories and files to target repo:**

```
Source → Target

CLAUDE.md                        → CLAUDE.md
.mcp.json                        → .mcp.json
install.sh                       → install.sh
cf                               → cf
.claude/                         → .claude/
docs/policy/                     → docs/policy/
docs/tasks/reports/.gitkeep      → docs/tasks/reports/.gitkeep
```

Use these commands (adjust paths):
```bash
SOURCE_REPO="/path/to/source"
TARGET_REPO="/path/to/target"

cp "$SOURCE_REPO/CLAUDE.md" "$TARGET_REPO/"
cp "$SOURCE_REPO/.mcp.json" "$TARGET_REPO/"
cp "$SOURCE_REPO/install.sh" "$TARGET_REPO/"
cp "$SOURCE_REPO/cf" "$TARGET_REPO/"
cp -R "$SOURCE_REPO/.claude" "$TARGET_REPO/"
cp -R "$SOURCE_REPO/docs/policy" "$TARGET_REPO/docs/"
mkdir -p "$TARGET_REPO/docs/tasks/reports"
touch "$TARGET_REPO/docs/tasks/reports/.gitkeep"
```

### 1A. Handle Empty Repository Edge Cases

**If the target repository is empty or freshly initialized** (no initial commit yet), `git ls-files` will return 0 files, causing `install.sh` to fail with "Cannot index empty repository."

**Diagnosis:**
```bash
git ls-files | wc -l
# If output is 0, no files are tracked yet
```

**Fix — Stage Essential Files Before Running install.sh:**

```bash
cd /path/to/target

# Stage at minimum: factory core files
git add CLAUDE.md .mcp.json install.sh cf .claude/ docs/

# Verify files are now tracked
git ls-files | wc -l
# Should show a positive count (at least 50+ files)

# Now you can run install.sh
./install.sh
```

**Why this matters:** `git ls-files` only returns **tracked** files (staged or committed). In a fresh repo with no commits, all files are untracked by default. Staging essential factory files makes them visible to `git ls-files`, allowing ctags to index them.

**Alternative:** If you prefer to commit first:
```bash
git add CLAUDE.md .mcp.json install.sh cf .claude/ docs/
git commit -m "Initial factory bootstrap"
./install.sh
```

Either approach works. The key is that files must be **tracked** (staged or committed) before `install.sh` runs.

### 2. Update .gitignore in Target Repo

**File:** `<target-repo>/.gitignore`

Add these entries (if not already present). Use the canonical form with a leading `/` and trailing `/` for directories:

```
# Factory MCP dependencies (installed by install.sh)
/.claude/mcp/node_modules

# Factory index state (generated by ctags)
/.claude/index-state.json

# Ctags index (regenerated per session)
/tags

# Factory runtime directories (generated at runtime, never committed)
/.claude/logs/
/.claude/cache/
/.claude/memory/
```

**Important:**
- Leading `/` anchors the pattern to the repo root (prevents matching nested paths).
- Trailing `/` ensures only directories are matched, not files with the same name.
- Do NOT add `docs/` or `docs/policy/` to `.gitignore` — policy files must be tracked.

### 3. Run install.sh

**In the target repository:**

```bash
cd /path/to/target
chmod +x install.sh
./install.sh
```

This will:
- Install MCP server dependencies (`.claude/mcp/node_modules`)
- Check/install system dependencies (rg, ctags, gemini CLI, jq, yq, tree)
- Generate initial ctags index
- Create `.claude/index-state.json`

### 4. Verify MCP Server Registration

**File:** `<target-repo>/.mcp.json`

Open the file and verify all 6 servers are registered:

```json
{
  "mcpServers": {
    "factory-tools": { "command": "node", "args": [".claude/mcp/server.js"] },
    "factory-ctags": { "command": "node", "args": [".claude/mcp/server-ctags.js"] },
    "factory-rg": { "command": "node", "args": [".claude/mcp/server-rg.js"] },
    "factory-fs": { "command": "node", "args": [".claude/mcp/server-fs.js"] },
    "factory-git": { "command": "node", "args": [".claude/mcp/server-git.js"] },
    "factory-query": { "command": "node", "args": [".claude/mcp/server-query.js"] }
  }
}
```

### 5. Test MCP Server Startup

**In the target repository:**

Test each server starts without errors:

```bash
cd .claude/mcp
node server.js < /dev/null &
PID=$!
sleep 1
kill $PID 2>/dev/null

node server-ctags.js < /dev/null &
PID=$!
sleep 1
kill $PID 2>/dev/null

# Repeat for all 6 servers
```

Or use the smoke test built into install.sh (it should have already run).

### 6. Run Verification

**In the target repository:**

```bash
./.claude/scripts/verify.sh
```

This runs a quick verification (7 critical checks in <3 seconds):
- Git repository detected
- Node.js available
- MCP dependencies installed
- All 6 MCP server files present
- All 8 agent files present
- Policy directory exists with >=12 files
- Tags index exists and is non-empty

For a comprehensive check, run:

```bash
./.claude/scripts/verify.sh full
```

This delegates to `health-check.sh` (all dependencies) and `validate-policies.sh` (policy integrity).

All checks should pass (✅). If any fail, address them before proceeding.

### 7. Open Target Repo in Claude Code

**In Claude Code:**

1. File → Open Folder → select target repository
2. Wait for Claude Code to load the `.mcp.json` and start the MCP servers
3. Run `/mcp` slash command to verify all 6 servers show as connected

Expected output:
```
Connected MCP servers:
  - factory-tools
  - factory-ctags
  - factory-rg
  - factory-fs
  - factory-git
  - factory-query
```

### 8. Adapt CLAUDE.md to Target Project

**File:** `<target-repo>/CLAUDE.md`

Update project-specific references:
- Replace any source project names/paths with target project names
- Verify the SYSTEM ARCHITECTURE diagram reflects the target repo structure
- Confirm policies are appropriate for the target project

If the target repo has project-specific requirements (e.g., different build tools, test frameworks), document them in CLAUDE.md or create a project-specific policy file in `docs/policy/`.

### 9. Test the Factory with a Simple Task

**In Claude Code (with target repo open):**

Send a simple test prompt to verify the factory is operational:

```
Create a new file at docs/test.md with the content "Factory is working."
```

Expected behavior:
- Manager detects single task
- Manager sends start notification (audible if macOS)
- Manager spawns Analyst → Architect → Developer → Reviewer → Tester → Reporter
- Reporter writes TASK_REPORT.md to docs/tasks/reports/
- Reporter sends completion notification (audible if macOS)
- File docs/test.md is created with the expected content

If this completes successfully, the factory is bootstrapped.

### 10. Clean Up Test Artifacts

**In the target repository:**

```bash
rm docs/test.md
rm docs/tasks/reports/TASK_REPORT.md
git status  # Verify no unexpected files remain
```

### 11. Commit Factory Infrastructure

**In the target repository:**

**Important distinction — Tracked vs Untracked:**
- If you followed Step 1A and **staged files** before running `install.sh`, those files are already in the git index (tracked but not committed). Use `git commit` (no `git add` needed).
- If you did **not** stage files (or committed them already), use `git add` before committing.

Check current status:
```bash
git status
# If files show as "Changes to be committed" → already staged, skip git add
# If files show as "Untracked files" → need git add
```

**Commit order guidance:**

The factory generates several files at runtime that should **not** be committed:
- `tags` (ctags index, regenerated per session)
- `.claude/mcp/node_modules/` (npm dependencies, installed via install.sh)
- `.claude/index-state.json` (ctags incremental state)
- `.claude/logs/` (cf runner logs)
- `.claude/cache/` (runtime cache database)

Ensure your `.gitignore` excludes these (see Step 2). Then commit:

```bash
# If files are NOT already staged (check git status first):
git add CLAUDE.md .mcp.json install.sh cf .claude/ docs/policy/ docs/tasks/

# Commit (works whether files are pre-staged or not)
git commit -m "Add autonomous multi-agent software factory

- Add factory orchestration system (CLAUDE.md)
- Add 6 MCP servers (factory-tools, factory-ctags, factory-rg, factory-fs, factory-git, factory-query)
- Add 8 specialized agents (Analyst, Researcher, Architect, Developer, Reviewer, Tester, Reporter, Reader)
- Add governance policies (orchestration, build, agents, workflow, spawn-templates, critical-rules)
- Add runbooks (add-mcp-server, add-agent, bootstrap-new-repo, add-test-suite)
- Add install script and health check
- Add ctags indexing for symbol navigation

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>"
```

**Post-commit verification:**
```bash
git status
# Should show: "working tree clean" or only runtime files (tags, node_modules, etc.) as untracked

git ls-files | grep -E "^\.claude/mcp/node_modules/|^tags$|^\.claude/index-state\.json$"
# Should return NOTHING (these should be gitignored, not tracked)
```

## Verification Checklist

- [ ] All factory files copied to target repository
- [ ] `.gitignore` updated with factory artifacts
- [ ] `install.sh` runs successfully
- [ ] All 6 MCP servers registered in `.mcp.json`
- [ ] All 6 MCP servers start without errors
- [ ] `health-check.sh` passes all checks (✅ on every line)
- [ ] Claude Code shows all 6 MCP servers connected (`/mcp` command)
- [ ] CLAUDE.md adapted to target project (if needed)
- [ ] Test task completes successfully (all phases run)
- [ ] Factory committed to target repository

## Common Pitfalls

1. **Forgetting to run install.sh.** The factory will not work without MCP dependencies and ctags index.
2. **Missing system dependencies.** Install ripgrep, universal-ctags, gemini CLI, jq, yq, and tree before running install.sh.
3. **Wrong Node.js version.** MCP servers require Node.js 16+ (ESM support).
4. **Path issues in .mcp.json.** The `args` array must use relative paths from the repository root (e.g., `.claude/mcp/server.js`, not `server.js`).
5. **Not verifying MCP connection.** Always check `/mcp` output in Claude Code. If servers don't connect, check the logs (Help → Show Logs).
6. **Skipping health check.** `health-check.sh` catches most setup issues early.
7. **Not adapting CLAUDE.md.** If the target project has unusual structure/tools, update CLAUDE.md policies.
8. **Copying node_modules.** Do NOT copy `.claude/mcp/node_modules` from source. Run `install.sh` to install fresh.
9. **Forgetting docs/tasks/reports/.** This directory must exist for the Reporter to write task reports.
10. **Not testing the factory.** Always run a simple test task before considering bootstrap complete.
